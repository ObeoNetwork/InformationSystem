h1(#interaction_tooling). ISD - Diagrammes d'interaction

h2(#presentation). Présentation

Les diagrammes d'interaction permettent de définir des diagrammes de séquence sur quasiment la totalité des éléments définis dans IS Designer, **à l'exception du métamodèle Database**.

Les diagrammes d'interaction manipulent des concepts très proches des diagrammes de séquence UML.

h2(#model_creation). Création d'un modèle d'interaction

Un assistant de création de modèles d'interaction est accessible via le menu :

bq. _File > New > Other... > Interaction Model_ (catégorie _IS Designer_)

!pics/interaction/NewWizard-InteractionModelSelection.png!

Cet assistant permet de définir :
* le nom du modèle à créer (l'extension du modèle est automatiquement ajoutée à la fin du nom en grisé et en italique s'il n'y a pas d'extension précisée),
* le projet ou répertoire de destination pour cette nouvelle ressource :

!pics/interaction/ModelCreationWizard-NameAndLocation.png!

Une fois l'assistant validé, le modèle est créé.

h2(#modeler_usage). Utilisation du modeleur

h3(#diagram_creation). Création d'un diagramme d'interaction
 
Pour créer un diagramme d'interaction, activer le point de vue _Interaction_ via le menu contextuel _Viewpoints Selection_ du projet ou du fichier @*.aird@.

Une fois le point de vue activé, sélectionner _New interaction_ dans le menu contextuel des éléments pour lesquels un diagramme d'interaction peut être créé.

!{max-width:100%}pics/interaction/ModelExplorerContextMenu-NewInteraction.png!

Un objet _Interaction_ et un diagramme de séquence sont alors créés et visibles sous l'objet sélectionné.
Il est possible de créer autant de diagrammes de séquence que voulu pour un même objet.

!pics/interaction/ModelExplorer-InteractionDiagram.png!

h3(#diagram_navigation). Navigation dans les diagrammes

Étant donné qu'il y a très peu de contraintes sur l'emplacement d'un diagramme d'interaction, il peut être utile d'utiliser l'arborescence par point de vue pour le retrouver, comme décrit dans le chapitre "ISD - Environment tooling":../../org.obeonetwork.dsl.environment.design.doc/doc/ISD%20-%20Environment%20tooling.html de la documentation.

h3(#diagram_tools). Éléments affichés et palette d'outils

Les éléments suivants sont affichés sur le diagramme :
* _Participant_ : définit une ligne de vie.
* _Call_ : message échangé entre deux participants. Les messages peuvent être des appels simples, des messages de retour, des messages de création ou des messages de destruction.
* _Execution_ : une exécution représente un moment où un participant est actif et effectue des traitements.
* _StateInvariant_ : utilisé pour indiquer un état obtenu à ce moment du diagramme.
* _InteractionUse_ : lien vers un autre diagramme d'interaction.
* _CombinedFragment_ et _Operand_ : ces concepts sont utilisés pour représenter des boucles ou des traitements conditionnels.

Les outils fournis par la palette sont :

| !pics/interaction/tools/SequenceDiagramPalette-CreateAsynchronousCall.png! | Création d'un message d'appel asynchrone. Un message d'appel et une zone d'exécution sur le participant appelé sont créés. L'appel étant asynchrone, aucun message de retour n'est créé. |
