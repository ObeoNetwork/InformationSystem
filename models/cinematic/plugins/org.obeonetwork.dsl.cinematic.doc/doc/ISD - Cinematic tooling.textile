h1(#cinematic_tooling). ISD - Outillage Cinematic

h2(#presentation). Présentation

Cinematic Designer est un outil de conception d'écrans d'application, permettant de décrire la structure d'une IHM (modélisation statique) et son comportement (modélisation dynamique).

Cinematic Designer apporte le point de vue _Cinematic Views_ qui permet de :

* Modéliser des vues et des éléments de vues (les composants graphiques d'une IHM),
* Modéliser la structure de la disposition graphique sous une structure de type « Grid Layout »,
* Modéliser les états et le flot entre les états de l'application,
* Organiser les _Flow_ et les _ViewElement_ en packages.

h2(#model_creation). Création des modèles

h3(#cinematic_model_creation). Création d'un modèle Cinematic

Un assistant de création de modèles Cinematic est accessible via le menu :

bq. _File > New > Other... > Cinematic Model_ (catégorie _IS Designer_)

Ou bien le menu contextuel sur un projet :

bq. _New > Other... > Cinematic Model_ (catégorie _IS Designer_)

Ou encore le raccourci clavier

bq. @Ctrl+N@

!pics/cinematic/NewWizard-CinematicModelSelection.jpg!

Cet assistant permet de définir :

* le nom du modèle à créer (l'extension du modèle est automatiquement ajoutée à la fin du nom en grisé et en italique s'il n'y a pas d'extension précisée),
* le projet ou répertoire de destination pour cette nouvelle ressource.

!pics/cinematic/ModelCreationWizard-NameAndLocation.png!

La dernière page de l'assistant permet de définir le toolkit à utiliser, et d'initialiser le modèle avec un diagramme de Mockup et un diagramme de Flow :

!pics/cinematic/ModelCreationWizard-ToolkitAndInitialDiagrams.jpg!

Une fois l'assistant validé, le modèle est créé, ainsi que les représentations _Package Diagram_ et _UI Structure_. Les représentations demandées en création sont ouvertes pour commencer à modéliser.

!pics/cinematic/ModelExplorer-InitialRepresentations.jpg!

Lorsqu'un modèle Cinematic est créé à l'aide de cet assistant dans un _Modeling Project_, les points de vue _Cinematic Views_ et _Environment Views_ sont automatiquement activés.

Le point de vue _Cinematic Views_ permet de visualiser et modifier un modèle Cinematic via plusieurs types de diagrammes tels que décrits dans la section suivante. Le point de vue _Environment Views_ contient la définition des vues de propriétés.

h2(#viewpoint_activation). Utilisation du modeleur

h3(#modeling_project_usage). Utilisation d'un projet de modélisation

Les points de vue _Cinematic Views_ et _Environment Views_ sont automatiquement activés lors de la création du modèle avec l'assistant dans un _Modeling Project_. Aucune activation manuelle n'est nécessaire.

Le menu contextuel _Viewpoints Selection_ du projet permet de vérifier les points de vue sélectionnés.

!pics/cinematic/ViewpointsSelection-CinematicViews.jpg!

h3(#other_project_type_utilisation). Utilisation d'un autre type de projet

Si le projet est d'un autre type, il manque alors un fichier _representations file_ (fichier @.aird@). L'action de menu contextuel _Configure > Convert to Modeling Project_ permet de remédier à cette situation.

Pour ajouter le modèle Cinematic à un _representations file_ existant, choisir _Add Model_ dans le menu contextuel du _Project Dependencies_, puis sélectionner la ressource du modèle Cinematic.

Après l'ajout d'un modèle Cinematic à une session existante, sélectionner les points de vue _Cinematic Views_ et _Environment Views_ dans le menu contextuel _Viewpoints Selection_ du projet s'ils ne sont pas déjà activés.

Cette représentation fournit en outre le moyen d’associer un toolkit au modèle Cinematic. Le toolkit est un modèle externe définissant les widgets utilisables pour la définition des écrans.

h4(#mockup_layout_structure). Structure de disposition graphique

Chaque repositionnement ou redimensionnement de _ViewElement_ sur ce diagramme déclenche la mise à jour de la structure de _Layout_ du _ViewContainer_ représenté sur le diagramme :

!pics/cinematic/mockup/ModelExplorer-LayoutStructure.png!

La structure de _Layout_ porte les positionnements graphiques des éléments du Mockup, organisés en structure de type « Grid Layout ». Un élément de Layout est défini par une position (coordonnées x, y), une taille (largeur, hauteur), une direction (horizontale ou verticale) et une liste de Layout fils.
L'algorithme de mise à jour de la structure de Layout procède à une analyse de l'espace en passes successivement verticales et horizontales. Dans l'exemple ci-dessus, l'espace est découpé verticalement en quatre compartiments, dont le dernier est découpé horizontalement en deux compartiments lors d'une deuxième passe.

Le choix de direction est déterminé par la direction dans laquelle l'espace se découpe le plus, avec en cas d'égalité un choix par défaut en découpage vertical.

Un élément de _Layout_ peut être lié ou non à un _ViewElement_ suivant qu’il représente le Layout d’un _ViewElement_ ou bien le Layout d'un espace structurant (tel que le Layout qui englobe les deux boutons de l'exemple ci-dessus).

Le diagramme _Layout Diagram_ permet de visualiser cette structure de Layout (décrite dans le chapitre suivant).

h4(#mockup_view_binding_edition). Édition de bindings

Afin de faire le lien avec les couches SOA et Entity, les _ViewContainer_ peuvent être liés par binding à des DTO ou des entités, et les _ViewElement_ peuvent être liés par binding à des attributs ou des références de DTO ou entités.

La fonctionnalité de binding est accessible en menu contextuel de la vue Mockup, sous l'entrée de menu _Binding..._.

Cette action de menu ouvre un dialogue de sélection permettant de lier par binding des DTO ou entités à un _ViewContainer_, ou des attributs ou références à un _ViewElement_.

Pour un _ViewContainer_, le dialogue présente les DTO ou entités accessibles :
!pics/cinematic/mockup/BindingDialog-ViewContainer.png!

Plusieurs DTO ou entités peuvent être sélectionnés. Chaque sélection ou désélection de DTO ou entité donne lieu à la création ou à la suppression d'un objet de binding _BindingInfo_.

Si un binding supprimé entraîne la suppression de bindings de références contenus, un dialogue de confirmation est affiché.

Si des _ViewContainer_ parents sont déjà liés par binding à des DTO ou entités, ces DTO ou entités sont sélectionnés et leur désélection est inactivée. La modification de ce binding est faisable dans le dialogue de binding du _ViewContainer_ parent en question.

Pour un _ViewElement_, le dialogue présente les DTO ou entités liés par binding aux _ViewContainer_ parents du _ViewElement_ sélectionné :

!pics/cinematic/mockup/BindingDialog-ViewElement.png!

Les DTO ou entités peuvent être dépliés pour accéder à des propriétés de DTO ou entités référencés. Plusieurs attributs ou références peuvent être sélectionnés. Chaque sélection ou désélection donne lieu à la création ou à la suppression d'un objet de binding _BindingReference_ contenu dans le _BindingInfo_ du _ViewContainer_ correspondant.

Lorsque des bindings sont définis sur un _ViewElement_ ou un _ViewContainer_, le glisser-déposer dans le diagramme de Mockup n'est possible que si les bindings restent valides avec le _ViewContainer_ destination.

h4(#mockup_view_navigation). Navigation vers d'autres diagrammes

Le double-clic sur les éléments du diagramme de Mockup permet de naviguer vers d'autres diagrammes en les créant à la volée s'ils n'existent pas :

* depuis le _ViewContainer_ racine vers le diagramme de Layout,

h3(#flow_diagram). Flow Diagram

h4(#flow_diagram_contents). Contenu

Le _Flow Diagram_ est défini sur un élément de type _Flow_.

!{max-width:100%}pics/cinematic/flow/FlowDiagram.png!

Sont affichés sur ce diagramme :

* Les états du Flow (InitialState, FinalState, ViewState, ActionState, DecisionState, AsyncEventState, SubflowState).
** Les types d'état sont différenciés par l'utilisation d'icônes et de pictogrammes distinctifs.
* Les transitions du Flow
** Si la transition est déclenchée par un (des) événement(s), le libellé principal de la transition est de la forme _!pics/cinematic/icons/ViewEvent.gif! evenement1,evenement2_.
** Si une garde est présente elle est affichée en libellé secondaire sous la forme _[guard]_.
** Si la transition est dirigée vers un _ViewState_, elle est représentée par une flèche pleine, sinon elle est représentée par une flèche pointillée.
* Un conteneur flottant nommé _FlowEvents_ présente les _FlowEvent_ génériques du _Flow_ de portée globale qui représentent des événements logiques ou métier. Ce conteneur peut être masqué en désactivant le calque _Flow Events_. Les événements de "Flow Events" portent l'icône !pics/cinematic/icons/FlowEvent.gif! pour les distinguer des événements définis dans le toolkit qui portent l'icône !pics/cinematic/icons/WidgetEventType.gif!.
* Les _ViewContainer_ référencés par les _ViewState_ affichés. Ceux-ci peuvent être masqués par la désactivation du calque _View Containers_.
** Les informations affichées pour les _ViewContainer_ sont les mêmes que pour le diagramme de Package décrit plus haut.

h4(#event_selection_dialog). Sélection des événements déclencheurs

!{max-width:100%}pics/cinematic/flow/EventSelectionDialog.png!

Ce dialogue permet de sélectionner des types d'événements. Il présente l’ensemble des types d’événements supportés par les widgets utilisés dans le modèle Cinematic, ainsi que l’ensemble des événements logiques définis dans le Flow.
Les événements des widgets sont classés sous la hiérarchie des View Elements, les événements logiques sont regroupés sous un nœud virtuel « Flow events ».

Les événements déclencheurs de la transition sont cochés.

La zone de filtre textuel permet de réduire le contenu de l’arbre de manière à n’afficher que les éléments dont le libellé se conforme au filtre. L’affichage d’un élément dont le libellé se conforme au filtre entraîne cependant l’affichage des éléments parents jusqu’à la racine de l’arbre ainsi que tous ses éléments fils. Le métacaractère ‘*’ est supporté pour correspondre à une chaîne de caractères quelconque et '?' pour correspondre à un caractère quelconque.

La case à cocher « Hide non contextual View Containers » permet de cacher les View Containers qui ne sont pas liés au View State source de la transition. À l’affichage du dialogue elle est cochée si au moins un View Container est lié au View State source.

L’arbre de sélection d’événement permet une sélection multiple. Le dialogue peut donc être validé avec une sélection vide, simple ou multiple.

À la validation du dialogue,

* Pour chaque événement de la transition dont le type est non présent dans la sélection :
** L’événement est retiré de la liste des événements déclencheurs de la transition.
** Si un événement de vue n'est pas utilisé par d'autres transitions il est supprimé.
* Pour chaque type d’événement sélectionné :
** Si l’événement de vue correspondant au type d’événement n’existe pas dans le View Element, il est créé (avec un nom conforme au format <nom du widget>_<type d'événement>).
** L’événement correspondant au type d’événement est ajouté à la liste des événements déclencheurs de la transition.
** Si le View State source n’est pas lié au View Container du type d’événement sélectionné, ce lien est créé.

!{max-width:100%}pics/cinematic/flow/ViewContainerSelectionDialog.png!

La zone de filtre textuel permet de réduire le contenu de l’arbre de manière à n’afficher que les éléments dont le libellé se conforme au filtre. L’affichage d’un élément dont le libellé se conforme au filtre entraîne cependant l’affichage des éléments parents jusqu’à la racine de l’arbre ainsi que tous ses éléments fils. L'état partiellement coché d'une case indique que des sous-éléments sont sélectionnés. Les éléments partiellement cochés ne font pas partie de la sélection prise en compte à la validation du dialogue.

À la validation du dialogue, la liste des éléments associés au View State est mise à jour avec la sélection faite par l’utilisateur.

h2(#toolkit_creation). Définition de toolkits

h3(#toolkit_structure). Structure d’un toolkit

Le métamodèle Cinematic est extensible par définition de toolkits.

!{max-width:100%}pics/cinematic/toolkits/ToolkitMetamodel.png!

De manière succincte, la création d'un toolkit consiste en la création de widgets, et sous chaque widget la création des types d'événements qu'il peut déclencher.

Par exemple, un toolkit peut contenir un widget _button_ avec un événement _buttonPressed_.

!pics/cinematic/toolkits/ModelExplorer-ButtonWidget.png!

La création de toolkits est une tâche réalisée par l'équipe réalisant l'outillage de l'équipe d'analyse / conception / développement.
À ce titre, la définition de toolkits se fait par l'éditeur EMF arborescent classique.

Pour une meilleure expérience utilisateur il est possible d'associer une icône à chaque widget. Cette icône est affichée devant le nom des ViewElement utilisant le widget, et dans la palette du diagramme de Mockup.

h3(#widget_style). Style des widgets

Un _Widget_ peut définir un style. Le style porte les attributs suivants :

* @decorator@ : Chemin vers l’image svg qui décore le widget (cas de combo box, radio button, etc.)
* @decoratorPosition@ : position cardinale du décorateur (east pour combo box, west pour radio button, etc.)
* @decoratorVFill@ : booléen spécifiant si le décorateur doit suivre le redimensionnement vertical (valeur par défaut égale à vrai)
* @decoratorHFill@ : booléen spécifiant si le décorateur doit suivre le redimensionnement horizontal (valeur par défaut égale à faux)
* @bordered@ : booléen spécifiant si une bordure est visible (faux pour link ou pour label)
* @roundedCorners@ : booléen spécifiant si les coins doivent être arrondis (vrai pour button)
* @fontColor@ : couleur de la police de caractères utilisée pour le libellé. Les couleurs disponibles sont celles définies par la classe @org.eclipse.swt.SWT@ par les champs dont le nom commence par « COLOR_ ». Ainsi, une couleur désignée par la chaîne « BLACK » désigne le champ @org.eclipse.swt.SWT.COLOR_BLACK@.
* @fontUnderlined@ : booléen spécifiant si la police de caractères utilisée pour le libellé est soulignée (vrai pour link)
* @labelHAlignment@ : alignement du texte à gauche, droite, ou centre
* @defaultWidth@ : largeur par défaut utilisée à la création d’un View Element
* @defaultHeight@ : hauteur par défaut utilisée à la création d’un View Element
* @exampleExpression@ : Expression AQL définie dans le contexte du _ViewElement_ (la variable self est instance de _ViewElement_), définissant le libellé des _ViewElement_ sur le diagramme Mockup lorsque le calque _Example_ est activé
* @labelHidden@ : booléen spécifiant si le libellé du _ViewElement_ représentant ce _Widget_ doit être caché (utile pour les conteneurs tels que Page, Panel, ...)
