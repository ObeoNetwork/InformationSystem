h1(#requirements). ISD - Outillage de gestion des exigences

h2(#presentation). Présentation

L'outillage de gestion des exigences d'IS Designer apporte un ensemble d'outils permettant d'intégrer la gestion d'exigences d'un projet dans le processus de modélisation. Il est composé d'un éditeur permettant de saisir ses exigences et d'une vue gérant le lien entre les modèles et les exigences du projet.

h2(#model_creation). Création d'un modèle d'exigences

h3(#model_initialization). Initialisation d'un modèle d'exigences

Pour créer un modèle d'exigences, ouvrir l'assistant depuis le menu :

bq. _File > New > Other... > Requirement Model_ (catégorie _IS Designer_)

!pics/requirements/NewWizard-RequirementModelSelection.png!

Cet assistant permet de définir :

* le nom du modèle à créer (l'extension du modèle est automatiquement ajoutée à la fin du nom en grisé et en italique s'il n'y a pas d'extension précisée),
* le projet ou répertoire de destination pour cette nouvelle ressource.

!pics/requirements/ModelCreationWizard-NameAndLocation.png!

Une fois l'assistant validé, le modèle est créé, la représentation _Requirements Table_ est créée et ouverte afin de commencer l'édition.

!{max-width:100%}pics/requirements/ModelExplorer-CreatedRequirementModel.png!

Lorsqu'un modèle d'exigences est créé à l'aide de cet assistant, le point de vue _Requirements_ est activé. Dans le cas où un modèle Graal existe déjà dans le projet, le point de vue _Requirements (Graal consolidated view)_ est activé. Le point de vue _Requirements_ est décrit dans la section "Activation du point de vue Requirements":#requirement_viewpoint. Le point de vue _Requirements (Graal consolidated view)_ est décrit dans la section de documentation "ISD - Graal Methodology (ISD consolidated view)":../../org.obeonetwork.is.design.doc/doc/ISD%20-%20Graal%20Methodology%20(ISD%20consolidated%20view).html.

h3(#model_concepts). Concepts des modèles d'exigences

Trois concepts peuvent être manipulés dans un modèle d'exigences : le _Repository_, les _Category_ et les _Requirement_.

Le _Repository_ est l'élément racine du modèle. Il porte un nom, contient les catégories principales et peut référencer un élément de modèle.

Une _Category_ est un conteneur d'exigences. Elle sert à ordonner les exigences selon différents critères. Une catégorie porte un identifiant et un nom et peut contenir des sous-catégories et des exigences. Elle peut référencer un objet de modèle.

Enfin, un _Requirement_ modélise une exigence. Elle est typée selon les critères _Functional_ ou _Technical_ et peut porter un sous-type. Une exigence a un identifiant, un nom, un statut et une description (_Statement_).
Il est possible de définir sa provenance (_Rationale_), ses critères d'acceptation (_AcceptanceCriteria_) et de référencer un objet de modèle.
À noter qu'un _Requirement_ a aussi un numéro de version. Ce numéro de version est initialisé à 1 et peut simplement être incrémenté de 1 en 1 en utilisant le bouton _+1_ affiché sur la vue _Properties_ pour l'exigence.

h2(#requirement_viewpoint). Activation du point de vue Requirements

L'outillage de gestion d'exigences embarque un point de vue permettant :

* La gestion des exigences (création, modification, suppression).
* La visualisation des exigences sous forme de matrices de traçabilité.

La création nécessite dans un premier temps l'activation du point de vue _Requirements_. Pour cela, sur une session _Viewpoint_ ouverte, lancer le menu

bq. _Viewpoint Selection_

Choisir le point de vue _Requirements_.

!pics/requirements/ViewpointSelection-Requirements.png!

h2(#representations). Représentations

h3(#requirements_table). Requirements Table

Une fois le point de vue activé, il est possible de créer un tableau _Requirements Table_ sur un _Repository_ d'exigences ou sur n'importe quelle _Category_. Il est ainsi possible de visualiser plus ou moins d'exigences selon le contexte choisi.

La création de ce tableau se fait via le menu :

bq. _New > new Requirements Table_

Ce tableau permet de créer, modifier et supprimer des catégories et des exigences.
Les informations sont affichées en colonnes dont le contenu peut être édité directement.
L'objet sélectionné peut aussi être modifié via la vue _Properties_.

!{max-width:100%}pics/requirements/RequirementsTable.png!

Le menu contextuel propose les actions suivantes :

* _Create Category_ : permet de créer une catégorie dans un _Repository_ ou une sous-catégorie en fonction du contexte.
* _Create Requirement_ : permet de créer une nouvelle exigence dans le contexte sélectionné.
* _Copy Category_ : permet de copier la catégorie sélectionnée et tout son contenu dans un emplacement à choisir.
* _Move Category_ : permet de déplacer une catégorie et tout son contenu dans un emplacement à choisir.
* _Copy Requirement_ : permet de copier une exigence à un emplacement à choisir.
* _Move Requirement_ : permet de déplacer une exigence vers un emplacement à choisir.
* _Validate requirements_ : permet de valider les exigences. En particulier les doublons sur les identifiants sont remontés en erreurs.

h3(#traceability_matrix). Requirements Traceability Matrix

Le point de vue permet de créer une matrice de traçabilité des exigences sur un _Repository_ d'exigences. La création de cette matrice se fait via le menu :

bq. _New > new Requirements Traceability Matrix_

!pics/requirements/NewRepresentationMenu-RequirementsTraceabilityMatrix.png!

Une matrice de traçabilité présente les éléments d'exigences du modèle en ligne et les éléments référencés en colonnes. Une croix est présente si l'exigence de la ligne référence l'objet de la colonne.

!{max-width:100%}pics/requirements/RequirementsTraceabilityMatrix.png!

Il est possible d'éditer les cellules. Si une cellule est vidée, la référence entre l'exigence et l'objet est supprimée.

h2(#linked_requirements_view). Vue Linked Requirements

h3(#linked_view_opening). Ouverture et contenu de la vue

La vue _Linked Requirements_ permet de lier les exigences aux éléments des modèles édités dans IS Designer. Ouvrir la vue depuis le menu :

bq. _Window > Show View > Other... > Linked Requirements_ (catégorie _Information System Designer_)

!{max-width:100%}pics/requirements/LinkedRequirementsView.png!

Cette vue est synchronisée avec l'éditeur actif dans IS Designer. Quand un élément de modèle est sélectionné, la vue se met à jour et présente toutes les exigences qui ont été liées à cet élément.

Cette vue porte cinq actions permettant de manipuler rapidement les exigences sans avoir à passer par l'éditeur décrit dans la partie précédente.

!{max-width:100%}pics/requirements/LinkedRequirementsView-Toolbar.png!


h3(#requirement_creation). Création d'une exigence

La première action permet de créer et de lier directement une nouvelle exigence à la sélection courante.

!pics/requirements/LinkedRequirementsView-CreateRequirementAction.png!

Au lancement de l'action, un assistant s'ouvre permettant de créer une nouvelle exigence. Toutes les propriétés de l'exigence peuvent être renseignées sur la première page. La seconde page permet de choisir la catégorie dans laquelle l'exigence va être positionnée. Dans le cas où celle-ci n'existe pas, il est possible d'utiliser le bouton _New Category..._ pour en créer une nouvelle.

!pics/requirements/CreateRequirementWizard-Properties.png! - !pics/requirements/CreateRequirementWizard-CategorySelection.png!

Une fois l'assistant validé, l'exigence est créée à l'endroit spécifié et est liée à l'objet actuellement sélectionné. La vue _Linked Requirements_ est mise à jour.

h3(#requirement_edition). Édition d'une exigence

La seconde action de la vue permet d'éditer une exigence présente dans la vue.

!pics/requirements/LinkedRequirementsView-EditRequirementAction.png!

Elle s'active en sélectionnant une exigence dans la liste des exigences liées et son lancement ouvre l'assistant d'édition de façon à pouvoir modifier les propriétés de cet objet.

h3(#requirement_linking). Association d'exigences

La troisième action permet de gérer l'association entre les éléments de modèle et les exigences.

!pics/requirements/LinkedRequirementsView-LinkRequirementsAction.png!

Le lancement de l'action ouvre une boîte de dialogue pour le choix des exigences à associer à l'élément actuellement sélectionné.

!pics/requirements/LinkRequirementsDialog.png!

h3(#requirement_unlinking). Dissociation d'exigences

La quatrième action permet de supprimer l'association entre une ou plusieurs exigences et l'élément actuellement sélectionné.

!pics/requirements/LinkedRequirementsView-UnlinkRequirementsAction.png!

Cette action s'active lorsqu'une ou plusieurs exigences sont sélectionnées parmi les exigences liées de la vue. Son lancement supprime tous les liens entre ces exigences et l'élément sélectionné.

Une boîte de confirmation s'ouvre au lancement de l'action pour limiter les erreurs de manipulation.

??L'utilisation de cette action ne supprime pas l'exigence du modèle. Seul le lien entre l'exigence et l'élément est supprimé. Il est tout à fait possible de créer un lien entre l'exigence et un autre élément.??

h3(#children_requirements). Exigences rattachées aux éléments fils

La cinquième action permet d'activer ou désactiver l'affichage des exigences liées aux éléments fils de l'élément sélectionné.

!pics/requirements/LinkedRequirementsView-ShowChildrenAction.png!

Avec l'option désactivée, seules les exigences directement rattachées sont affichées :

!pics/requirements/LinkedRequirementsView-DirectRequirements.png!

Quand cette option est activée, les exigences attachées à des éléments fils de l'élément sélectionné sont affichées en plus de celles rattachées directement à l'objet sélectionné.

Ces exigences sont affichées en gris et en italique pour permettre de les différencier.

De plus, en survolant une ligne, une infobulle contenant le nom de l'élément concerné s'affiche.

!pics/requirements/LinkedRequirementsView-ChildrenRequirements.png!

h2(#requirement_decorators). Décorateurs des exigences

h3(#decorator_display). Affichage et signification

Des décorateurs permettent de visualiser rapidement les éléments ayant au moins une exigence rattachée sans avoir à sélectionner l'élément ni à consulter le contenu de la vue _Linked Requirements_.

Ces décorateurs sont affichés dans la vue _Model Explorer_ et sur les diagrammes.

!pics/requirements/ModelExplorer-RequirementDecorators.png!
Vue _Model Explorer_

!pics/requirements/Diagram-RequirementDecorators.png!
Diagramme

Les décorateurs peuvent être de trois couleurs différentes :

* Gris : l'élément n'a pas d'exigence rattachée mais au moins un de ses enfants a une exigence rattachée.
* Orange : l'élément a au moins une exigence rattachée ainsi qu'au moins un de ses enfants.
* Jaune : l'élément a au moins une exigence rattachée mais aucun de ses enfants n'est dans ce cas.

h3(#decorator_activation). Activation et désactivation

Pour activer ou désactiver globalement les décorateurs, ouvrir le menu _Window > Preferences_, puis la rubrique _General > Appearance > Label decorations_. Cocher ou décocher _Object with requirements_.

!{max-width:100%}pics/requirements/Preferences-RequirementDecorators.png!
